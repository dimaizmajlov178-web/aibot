# Telegram Trading Bot

## Цель проекта
Telegram-бот, который самостоятельно торгует на бирже/у брокера от имени пользователя. Анализ решений — через DeepSeek. Бот привязывается по API-ключу брокера, умеет самообучаться на истории сделок. Доступ к боту — по подписке, которую выдаёт админ.

## Основные возможности

### Привязка брокера и контроль
- **Цель:** Пользователь подключает API-ключ брокера и видит состояние своего счёта.
- **Описание:** Пошаговая привязка ключа через `/connect` с тестовым вызовом balance. Команды `/status`, `/positions`, `/stats` показывают баланс, позиции, сделки и статистику. Ключ шифруется и хранится только в зашифрованном виде. До получения реального API брокера используется заглушка с фейковыми данными.
- **Критерии приёмки:**
  - Пользователь привязывает API-ключ брокера, бот делает тестовый вызов balance и сообщает результат.
  - `/status` показывает баланс, открытые позиции, дневной и общий P&L.
  - `/positions` показывает открытые и последние закрытые сделки.
  - `/stats` показывает винрейт, профит-фактор, средний R, максимальную просадку.
  - API-ключ хранится только в зашифрованном виде, админ не видит ключи пользователей.

### Автоматическая торговля с AI
- **Цель:** Бот самостоятельно анализирует рынок через DeepSeek и открывает/закрывает сделки.
- **Описание:** Торговое ядро собирает рыночные данные (OHLCV на нескольких таймфреймах, индикаторы RSI, MACD, EMA 20/50/200, ATR, объём, CVD, VWAP-отклонение), формирует структурированный промт для DeepSeek, парсит JSON-ответ с валидацией схемы и исполняет ордера через абстрактный клиент брокера. Цикл решений работает по таймеру и по событиям (закрытие свечи, резкое движение).
- **Критерии приёмки:**
  - AI-цикл формирует запрос к DeepSeek, парсит JSON-ответ и логирует каждый запрос/ответ.
  - Движок открывает и закрывает сделку через `broker.execute_order()`.
  - Невалидный ответ DeepSeek не приводит к ошибке: повторный запрос или пропуск цикла.
  - Каждый запрос и ответ логируются в `ai_decisions` (промт, ответ, latency, токены).

### Риск-контроль
- **Цель:** Защитить баланс пользователя от чрезмерных потерь.
- **Описание:** Жёсткие правила риск-менеджмента: максимальный % баланса на сделку (по умолчанию 1%), максимум одновременных позиций, дневная просадка выше лимита → автопауза до следующего дня, общая просадка выше лимита → автостоп с уведомлением админу, лимит сделок в день. Перед каждым ордером проверяются лимиты, маржа и whitelist символов. Защита от дублей через Redis-блокировку на символ+направление.
- **Критерии приёмки:**
  - Риск-менеджмент блокирует сделки при превышении лимитов.
  - При дневной просадке выше лимита торговля автоматически ставится на паузу до следующего дня.
  - При общей просадке выше лимита торговля останавливается и админ получает уведомление.
  - `/pause` и `/resume` позволяют пользователю остановить и возобновить торговлю.
  - `/settings` позволяет настроить риск на сделку, максимум позиций, список символов и режим AI.

### Самообучение
- **Цель:** Бот учится на истории сделок без дорогого fine-tuning.
- **Описание:** Каждая сделка сохраняет снимок контекста (рынок, индикаторы, решение AI, reasoning) и результат. Раз в сутки DeepSeek анализирует выборку последних сделок, выявляет паттерны успехов/неудач и предлагает корректировки правил. Изменения сохраняются как новые версии стратегии с автоматическим расчётом метрик (винрейт, профит-фактор, просадка). Поддерживается A/B режим сравнения стратегий, анти-оверфит ограничения (глубина истории, минимум сделок) и откат стратегии админом.
- **Критерии приёмки:**
  - Каждая сделка сохраняет снимок контекста и результат.
  - Раз в сутки генерируется learning-отчёт через DeepSeek.
  - При наличии изменений создаётся новая версия стратегии с метриками.
  - Админ может откатить стратегию на любую предыдущую версию.

### Подписки и админ-панель
- **Цель:** Админ управляет доступом пользователей к боту.
- **Описание:** Роли `admin`, `subscriber`, `guest`. Админ через `/admin` выдаёт и отзывает подписки, смотрит список пользователей, делает рассылку и глобальную паузу. Все защищённые хендлеры проверяют активную подписку.
- **Критерии приёмки:**
  - Админ выдаёт и отзывает доступ через `/admin` (`/grant`, `/revoke`).
  - `/users` показывает список пользователей.
  - `/broadcast` отправляет сообщение всем пользователям.
  - `/global_pause` останавливает торговлю у всех.
  - Пользователь без активной подписки не может пользоваться защищёнными функциями.

## Дополнительные заметки
- Стек: Python 3.11+, aiogram 3 (Telegram), FastAPI (админ-панель), DeepSeek API (deepseek-chat и deepseek-reasoner), PostgreSQL + SQLAlchemy 2.0 + Alembic, Redis, APScheduler, Docker + docker-compose, loguru.
- Архитектура: модульный монолит с папками `bot/`, `broker/`, `ai/`, `engine/`, `learning/`, `subscriptions/`, `admin/`, `db/`, `core/`. Все внешние интеграции (Telegram, Broker, DeepSeek) изолированы за интерфейсами.
- Стиль общения бота: строгий и лаконичный — короткие сообщения, цифры и таблицы, без лишнего текста.
- До получения документации брокера в `broker/` реализуются абстрактный `BaseBroker` и заглушка `StubBroker` с фейковыми данными, чтобы ядро и AI можно было тестировать без реального API.
- Безопасность: API-ключи шифруются (Fernet, ключ из `.env`), в БД хранится только шифр, все торговые действия и изменения настроек пишутся в `audit_log`, секреты только через `.env`.
- Тесты: pytest + pytest-asyncio, покрытие ядра ≥ 70%.
- Критерии готовности MVP: бот запускается и `/start` с `/help` работают; привязка ключа с тестовым вызовом balance; AI-цикл с парсингом JSON и логированием; движок открывает/закрывает сделки; риск-менеджмент блокирует превышения; админ выдаёт/отзывает доступ; ежедневный learning-отчёт; тесты на ядро, риск-менеджмент и парсинг AI-ответа; docker-compose поднимает всё одной командой.
